## 一、先建立架构心智（30 秒）

**realm = 每个服自成一个完整世界**，按"加服"横向扩容，不是全区全服；跨服只在需要时开**临时实例**（战场/跨服 BOSS）。所以：游戏数据默认是**本服内**的，别假设跨服可见。

**四类进程各司其职**（1 Gateway ↔ 1 GameServer ↔ N MapServer）：

| 进程 | 职责 | 有无游戏态 |
|------|------|-----------|
| **GlobalServer** | 账号、服务器列表 | 无游戏态（别往里塞玩法） |
| **GatewayServer** | 客户端连接、鉴权、消息路由 | 无（纯转发） |
| **GameServer** | 玩家逻辑、**持久数据权威**、进出图协调 | 持久态（落库） |
| **MapServer** | 空间/AOI/战斗/tick、**瞬时模拟权威** | 瞬时态（不落库） |

**一个玩家有两个化身**——这是最重要的心智：

- **GameServer `player.Player`（Actor）** = 持久业务权威：背包 / 技能 / 货币 / 钻石 / 经验 / 等级 / 任务 / 仓库 / 邮件。跨登录持久，**落库**。
- **MapServer `object.Player`** = 瞬时模拟权威：血量 / 位置 / 朝向 / 战斗内 buff / 仇恨。随进出图/战斗存续，**不落库**。

数据流（典型）：`客户端 → Gateway → GameServer(持久逻辑) →(进场快照)→ MapServer(空间/战斗) →(AttrGrant 回流持久变更)→ GameServer → 落库`。

## 二、七条架构铁律（开发游戏功能前必须内化）

这七条是本项目反复踩坑后沉淀的**红线**。每条都对应过真实缺陷——违反 = 重蹈覆辙。

### 铁律 1 · 权威边界：持久走 GameServer，瞬时在 MapServer，MapServer 绝不写库
- **规则**：任何**跨登录持久**的数据（背包/货币/等级/任务/称号…）权威在 GameServer 的 `player.Player` actor，只由它落库。MapServer 只持有**瞬时**态（血/位/buff）。
- **为什么**：两处都能写库 = 双写者，必然出现覆盖/丢失/不一致。
- **正确姿势**：MapServer 战斗产生的持久变更（掉落/经验/货币）**不自己写库**，打包成 `AttrGrant` 事件回流给玩家的家 GameServer 落库。
- **锚点**：`realm架构-详细设计.md §④`；`zCommon/crossserver/internal_ids.go`（`MsgInternalAttrGrant=508`、`AttrKind`）。

### 铁律 2 · MAP-2 单写者：碰地图对象字段必经 `Map.Do`
- **规则**：读/写 `*object.Player`（或任何地图对象）的字段，必须在**该地图的 actor goroutine** 上进行——即包进 `m.Do(func(){ ... })`。**绝不在网络 goroutine 上裸读写对象字段。**
- **为什么**：每张地图是单写者 goroutine（`map_actor.go`），tick/AI/战斗都在它上面跑；网络 goroutine 直接碰字段 = 与之并发 = 数据竞争（`-race` 必报）。本会话的无缝交接就栽在这（在网络 goroutine 裸读 `GetHealth`/裸写 `SetLevel`）。
- **正确姿势**：`Map.Do` 是**同步**的（投递到 actor 并等完成，可拿返回值）；跨两张图的操作分别用各自的 `Do`。地图内部辅助方法（`*Locked`）已在 actor 上，**不要再自投递 `Do`**（自投递死锁）。
- **锚点**：`MapServer/maps/map_actor.go`（`Do`/`run`/注释）；范例修复 `MapServer/maps/seamless.go` + 守护测试 `seamless_test.go`。

### 铁律 3 · 客户端视野只由 MapServer 分层 AOI 驱动，别自建第二套 AOI
- **规则**：客户端的 `实体进入/离开/移动视野`（AOI）**唯一**来源是 MapServer 每层各自的网格 AOI，经 `crossserver 500-505 → GameServer map_service.HandleAOINotify → 推客户端`。
- **为什么**：曾经 GameServer 另建了一套按 `logicalMapID` 键值、**不感知分线**的本地 AOI，导致不同层的玩家互相串视野（②-b 血泪）。两套 AOI = 迟早不一致。
- **正确姿势**：需要"视野内广播"（血量/buff/死亡/自定义）时，走 MapServer AOI 通道扩展，不要在 GameServer 侧按地图重建对象表做范围查询。
- **锚点**：`realm架构-详细设计.md` §② 的"实现补正（②-b）"；`GameServer/game/player/player_aoi_handler.go`（6 类 AOI 推送模板）。

### 铁律 4 · 分线透明：op 经 `resolveMap` 定位；分配/回收类资源用"在途预留额度"
- **规则**：可分线的逻辑图（如主城），玩家实际在**派生层图**里。进图后一切 op（移动/攻击/拾取/离开）必须经 `resolveMap(playerID, mapID)` 定位到玩家真正所在的层，不能直接用客户端传的 `logicalMapID`。
- **为什么**：直接用逻辑图 ID 会打到空图或错层。另外，"选层/建层 + 加人"若不原子，并发进图会击穿 softCap/hardCap（TOCTOU），空层回收还会和"正在进入"打架。
- **正确姿势**：新增任何"按人数分配 + 空置回收"的资源，参照分线的 `reserved` 在途预留额度模式（选中即占额、计入 cap 判定、加入后归还、预留期间不回收）。
- **锚点**：`MapServer/maps/layer_manager.go`（`AllocateLayer`/`resolveMap`）、`instance_manager.go`（`reserved`/`ReapEmpty`）、守护测试 `layer_manager_test.go`。

### 铁律 5 · realm 隔离：每服自成世界，跨服玩法走临时实例
- **规则**：默认所有游戏态是**本服**的。不要引入"进程内全局、跨服共享"的状态。
- **为什么**：realm 的核心价值是隔离（数据/进程/发现按 GroupID 分组，一服崩不影响别服）。
- **正确姿势**：确实要跨服（跨服战场/BOSS）时，走 `InstanceKindCrossServer` 临时实例 + 结果按玩家归属 `AttrGrant` 回流各自家服；不同区服的"合并"是互联服机制（`realm架构与跨服设计.md §5.2`），另说。
- **锚点**：`MapServer/maps/instance_manager.go`（`CreateInstance`）；`realm架构-详细设计.md §③/§5.1`。

### 铁律 6 · 契约先行：跨服消息只经唯一编解码源
- **规则**：任何跨服（Game↔Map）消息的线格式与 ID，只在 `zCommon/crossserver/codec.go` 定义；改动同步更新 `协议契约.md` 并加/更契约测试。客户端 proto 放 `resources/protocol/`。
- **为什么**：编解码分散 = 两端漂移 = 疑难 bug。
- **锚点**：`docs/协议契约.md`；`zCommon/crossserver/codec.go` + `codec_test.go`。

### 铁律 7 · 幂等 + 崩溃安全：发放/消耗/回流必须可重复投递而不翻倍
- **规则**：一切"加性变更"（加经验/加货币/加物品/回流结算）带唯一 `requestID`，接收侧去重（`inbox.TryAccept`）；消耗类在 actor 侧校验余量（CAS），不足则拒绝并回执。
- **为什么**：网络重投/重连/崩溃恢复都可能重复送达，不幂等就会重复发放或扣成负数。
- **锚点**：`AttrGrant`(508) 的 requestID 幂等；可选崩溃安全走 `zCommon/consistency` 的 Outbox/Inbox。

## 三、加功能配方（按类型）

先用下表定位你要动哪些进程/文件，再看对应步骤。**每类都以铁律为约束。**

| 功能类型 | 主要落点 | 关键铁律 |
|---------|---------|---------|
| A. 纯玩家逻辑请求（查询/背包操作/社交） | GameServer | 1,6,7 |
| B. 新增持久玩家数据（称号/成就/货币种类…） | GameServer + DB（+ 进场快照下发 MapServer） | 1,6,7 |
| C. 空间/战斗/场景玩法（技能效果/采集/AOI 广播） | MapServer | 2,3,4 |
| D. 新增一张地图 | 配置 + 分线/无缝登记 | 4,5 |
| E. 跨服玩法 | MapServer 临时实例 + 回流 | 5,1,7 |

### ⚠ 配方成熟度（动手前必看）

不同配方的地基成熟度不同——**照抄前先确认锚点函数有没有生产调用者**，否则会撞上"函数在、但没接进 live、也没配置喂它"的半死件：

| 配方 | 成熟度 | 关键提醒 |
|------|--------|----------|
| **A 消息** | ✅ 直接做 | 模板化（`handler/message/item_handler.go` 是完美模板）、有 E2E。注意 dispatch 有 3s 回调超时，handler 内别做跨服往返。 |
| **C 玩法/AOI** | ✅ 直接做 | MAP-2 单写者 + AOI 单一权威 + 出向回流都真、有 E2E + t1 race。 |
| **B 持久数据** | ⚠ 部分（有半死件） | 标量属性(level/gold…)与列表资产(背包/技能…)走**两套持久化路径**；加标量属性**务必补 `login_service.go` 的登录载入**（漏了=登出零值覆盖清零）。**进场快照已接**：GameServer `sendMapEnterRequest` 从玩家 actor 取只读快照（level/hp/…）下发、MapServer `HandlePlayerEnterMap` 据此 `SetLevel/SetHealth`（不再恒 level 1）；attack/defense 仍由 strength/stamina 派生（无直接下发通道，装备系统启用后再补）。资产存盘非崩溃安全（未接 Outbox/Inbox）。 |
| **D 地图** | ✅ 可做（配置已接） | Excel `map.xlsx`→`CreateMap`（尺寸/人数）可用；**刷怪点**在 `SpawnManager.Init` 按 mapConfigID 表驱动、**传送点**在 `CreateMap` 按表 `GetTeleportPointsByMapID` 装（原来只在死路径 `CreateMapFromResource`）；**分线/无缝**由 `[Maps]` ini 的 `LayerableMaps`+`LayerSoftCap/HardCap` 与 `SeamlessLinks` 生产驱动（`ZMMO_TEST_LAYER` 仅测试夹具）。事件/建筑/资源点表已有 loader 但 Map 侧尚未接 apply（要用再补，勿假接）。 |
| **E 跨服** | ❌ 物理路由从零造 | 实例机制(建/销/空置回收)+ AttrGrant 回流 + codec 编解码**都真**；但**入口整条零生产接线**（`CrossServerMapEntry`/`MigrationManager` 零调用）、**服务发现按 realm 锁死**（GameServer 只发现本 group 的 MapServer、跨 realm 连不上）、无匹配/分配服务。跨服玩法的物理路由（跨 realm 发现/连接 + 匹配分配 + 流量导入）**要从零造**，按此估工，别按"接线"估。 |

**一句话**：A/C/D 照抄即可；B 先看清半死件（登录载入、崩溃安全）；E 的物理跨服路由是从零工程（见 [realm架构-详细设计.md](realm架构-详细设计.md) §5.1）。

### 配方 A：加一条客户端请求/响应（纯 GameServer 逻辑）
1. `resources/protocol/*.proto` 加请求/响应消息 + `MsgId`，regen `.pb.go`。
2. GameServer 注册 handler，路由到玩家 actor 处理（在 actor 内改持久态，铁律 1）。
3. 需要落库的变更走玩家 actor 的落库路径；返回响应。
4. 测试：handler 单测 + 真 E2E（客户端真收到响应、DB 真变化）。

### 配方 B：加一项持久玩家数据（例：称号）
1. **建表 + DAO**：`GameDB_区服ID` 加表，DAO 按分片规则（别绕分片缝）。
2. **玩家 actor 加字段 + 加载/落库**：`player.Player` 加字段，登录时加载、变更时落库（铁律 1、7 幂等）。
3. **协议**：加设置/查询消息（配方 A）。
4. **（若 MapServer 要用）进场快照下发**：玩家进图时把该数据作为**只读快照**下发给 MapServer 初始化 `object.Player`——**只读、不是第二权威**（铁律 1）。
5. **（若 MapServer 会产生该数据的持久变更）走回流**：MapServer 不写库，打 `AttrGrant` 回流（铁律 1、7）。
6. 测试：真 E2E（设置→重登仍在=持久；若涉及 MapServer→回流后 DB 一致）。

### 配方 C：加空间/战斗/场景玩法（MapServer 侧）
1. 在 MapServer 地图/对象上实现逻辑，**所有对象字段读写经 `Map.Do`**（铁律 2）。
2. 需要"视野内其他玩家看到"→ 走 MapServer AOI 广播通道（铁律 3），不要在 GameServer 侧重建。
3. 周期性逻辑接 tick（经 `postTick`，别从外部 goroutine 直接驱动地图帧更新——会锁序反转死锁）。
4. 产生的持久结果 → `AttrGrant` 回流（铁律 1）。
5. 测试：MapServer 单测（可直接构造 `*Map`，actor 会启动）；跨层/并发场景加 `-race` 守护（在 t1 race runner 跑，见 §四）。

### 配方 D：加一张地图
1. 地图配置（`map.xlsx` 加行 + `MapServer` ini 的 `[Maps] MapIDs` 加该图 ID，见 `规范.md`）。刷怪点/传送点在各自配置表加行即自动装（`CreateMap` 落地）。
2. **是否可分线**：热点开放图 → `[Maps]` ini 加 `LayerableMaps=<该图ID>` + `LayerSoftCap`/`LayerHardCap`（生产由 ini 驱动，别再用 `ZMMO_TEST_LAYER` 夹具）；否则普通单图。
3. **是否无缝相邻**：连续大陆的相邻分区 → `[Maps]` ini 加 `SeamlessLinks=a-b`（双向登记）；否则跨图走普通 enter/leave（铁律 4、并见 realm 详设 §①）。
4. **实例类型**：副本/战场/跨服 → 经 `CreateInstance(kind, ...)`（铁律 5）。
5. 测试：进图路由正确、（分线图）多客户端分到不同层、AOI 隔离。

### 配方 E：跨服玩法
1. `CreateInstance(InstanceKindCrossServer, ...)` 建临时实例（铁律 5）。
2. 玩家来自多服、结果按归属 `AttrGrant` 回流各自家服（铁律 1、7）。
3. 空置由 `ReapEmpty` 自动回收。
4. 物理跨服路由（把 B 服玩家送进 A 服实例）属跨服匹配 + 网关路由职责，见 realm 详设 §5.1。

## 四、测试与验收（realm/游戏功能特有）

通用验证纪律见 `开发约定与工作流.md`（自评不可信、真 E2E = 跨进程断言、多模块逐一 build）。本文补 realm 特有：

- **分线隔离 E2E**：两客户端进同一可分线图（`ZMMO_TEST_LAYER=<mapID>` 门控 softCap=1）→ 分到不同层 → 客户端 `[AOI]` 视野互不含对方（GameClient 已内置 AOI 视野观测）。
- **回流落库 E2E**：MapServer 击杀/结算 → 玩家家 GameServer 落库，直查 DB 断言（不是客户端本地编造的响应）。
- **AOI 单一权威**：同图能互见、分层不能，且每事件只投一次（无重复推送）。
- **并发正确性用 `-race`**：本机 Windows 无 gcc 跑不了 `-race`；在 **t1 race runner**（`~/zrace/{zEngine,zUtil,zMmoServer}`，go1.25.5 + gcc）跑：本机无 rsync → `tar czf - --exclude=.git | ssh potato@192.168.251.134 'cd ~/zrace/zMmoServer && tar xzf -'` 同步源码，再 `cd MapServer && CGO_ENABLED=1 go test -race ./maps/`（zLog 每条 Info 打调用栈，`tail` 会淹没真因，须存日志 `grep "DATA RACE"/"--- FAIL"`）。
- **测试客户端**：`GameClient`（`gclient.exe -mode full`）是端到端驱动工具；配方见项目记忆 `zmmoserver-realm-track`（18888 临时端口/新账号注册/AOI 观测/关键屏障已判 Result）。

# zMmoServer 项目评估报告（可验证事实版）

**版本**：0.0.8 ｜ **重写日期**：2026-07-24 ｜ **方法论**：真相优先，每条"完成"挂一个可复现的证据。

> **本报告为何重写（Phase 4.2）**：旧版（2026-04-20，"综合 4.91/5、端到端全绿"）是**不可信自评**的典型——
> 例如它把地图攻击 `Result=1(目标不存在)` 当作"符合预期 ✅"，而真相是 attack 链路当时**是断的**
> （GameServer 用无怪的本地地图越权校验拦死请求）。此类"看起来对"的结论正是本项目要根除的。
> **本版废弃一切主观打分**，改为「能力 → 证据」清单：每条"已完成"都指向一个通过的测试或一次
> 跨进程真 E2E（含可复现命令/观测）。进度的权威真相源是 [`成熟化改造-执行计划.md`](成熟化改造-执行计划.md) 的勾选框；
> 工作与验证方法见 [`开发约定与工作流.md`](开发约定与工作流.md)。

## 四、如何复现（任何人/AI/CI）

```powershell
# 1) 全模块 build+vet 门禁
powershell -ExecutionPolicy Bypass -File D:\GitHub\zMmoServer\scripts\ci-check.ps1

# 2) 引擎守护测试
go -C D:\GitHub\zEngine test ./zActor/ ./zNet/ -count=1

# 3) 契约 + 领域模型
go -C D:\GitHub\zMmoServer\zCommon test ./crossserver/ ./game/ -count=1

# 4) 持久化（需 MySQL，未设 DSN 则自动 skip）
$env:ZMMO_TEST_MYSQL_DSN = "root:123456@tcp(<host>:3306)/global?parseTime=true&loc=Local"
go -C D:\GitHub\zMmoServer\zCommon test ./consistency/ -count=1

# 5) 端到端（四进程本机，含持久化开关）：见 开发约定与工作流.md 的 E2E 编排要点
```

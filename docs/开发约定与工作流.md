## 二、核心工作方法：一个可复制的工作环

每选一块任务，按这个环推进——它被反复验证能挖出并消灭潜伏缺陷：

```
勘察现有实现  →  找潜伏 bug  →  修  →  加真测试守护  →  真 E2E 证明  →  更新文档/记忆
   (读代码)     (未测代码必藏)              (锁定回归)      (跨进程/真DB)     (留证据)
```

要点：

- **一次只做一块，做完做透**：编译绿 + 测试绿 + E2E 绿 + 文档更新，才算完，再开下一块。
- **未跑到的路径必藏 bug**：本项目的经验反复印证——AOI 回程、Actor 监督、断线重连、连接去重、跨服回流，凡是"实现了但从没真跑过"的代码，一挖一个准。勘察时优先怀疑这类路径。
- **改动要窄、可回退**：宽面重构（如跨多处签名删死代码）先完整定位再动手，或拆成独立专注任务，别在长会话尾部硬上。
- **新特性默认 env/config 门控**：持久化、指标接入这类改动用环境变量门控，默认不改变原行为，便于灰度与回退。
- **业务层只做最少量**：只做够验证架构所需的业务，重点永远是整体架构，不堆玩法。
- **开发游戏功能前对齐架构铁律**：见 [游戏开发指南.md](游戏开发指南.md) 第二章（权威边界 / MAP-2 单写者 / AOI 单一权威 / 分线透明 / realm 隔离 / 契约先行 / 幂等崩溃安全）——它们对应过真实缺陷，违反=重蹈覆辙。

## 三、验证纪律：什么才算"证明"

**自评不可信**。项目历史上出现过"E2E 全绿"却是本地伪造响应、玩家从未真进入 MapServer 的情况。因此：

- **每个"完成"必须挂一个通过的测试或一次真 E2E**，不能只凭"看起来对"。
- **真 E2E = 跨进程断言**：查 MapServer 真实日志/状态、客户端真实收到的 protoId、真实 DB 行数——不是客户端本地编造的响应。
- **多模块必须逐一验证**：本仓库是多 module（各自 `go.mod` + `replace`，无 `go.work`），用一次 `ci-check` 跑全模块 build+vet。
- **并发相关跑 `-race`**：本机 Windows 无 C 编译器跑不了 `-race`，须在 CI/Linux 或有 gcc 的 race runner 上跑。

常用命令：

```powershell
# 全模块 build+vet 门禁（全绿才算过）
powershell -ExecutionPolicy Bypass -File D:\GitHub\zMmoServer\scripts\ci-check.ps1

# 单模块 build / vet / test（用 go -C，免 cd）
go -C D:\GitHub\zMmoServer\<Module> build ./...
go -C D:\GitHub\zEngine test ./zNet/ -run <TestName> -count=1 -timeout 40s -v

# 需 DB 的集成测试用环境变量门控，未设则 t.Skip（CI 无需 DB）
$env:ZMMO_TEST_MYSQL_DSN = "root:123456@tcp(192.168.251.134:3306)/global?parseTime=true&loc=Local&timeout=8s"
```

测试写法参考（自包含 + 强断言 + 对真实依赖验证）：`zCommon/crossserver/codec_test.go`、
`zEngine/zNet/metrics_test.go`、`zEngine/zActor/actor_test.go`、`zCommon/consistency/sql_store_test.go`、
`MapServer/maps/seamless_test.go`（并发 `-race` 守护）。

- **版本号用 `0.0.X` 递增**，成熟前**不发 1.0**；`0.0.X` 也别跳。
- **契约先行**：跨服协议、编解码只经唯一源（`zCommon/crossserver/codec.go`），改动同步更新 `协议契约.md` 并加/更契约测试。

## 五、环境与工具坑（踩过的）

- **Shell**：主用 PowerShell；Bash 工具的 `cd` 常失效——定目录跑 go 用 `go -C <dir>` 或 PowerShell `Set-Location`。
- **判成败用 `$LASTEXITCODE`**，别用 `2>&1`：PowerShell 会把 go 的 stderr 包装成 error record，即便退出码 0 也显红。
- **`Remove-Item` 用绝对路径**：相对路径 + 受保护根目录会被拦；删仓库内临时文件可用 Bash `rm -f <绝对路径>`。
- **gopls "undefined/could not import" 是假阳性**：本仓库无 `go.work`，编辑器会误报跨模块符号找不到——**以 `go build` 为准**，忽略这类红。
- **Windows 无 C 编译器 → `go test -race` 跑不了**：须在 CI/Linux 或有 gcc 的 race runner 跑（同步源码后 `CGO_ENABLED=1 go test -race`）。
- **多 module**：改了被依赖模块（zEngine/zCommon）后，务必 build 依赖它的上层模块（GameServer/MapServer 等）验证。
- **测试环境**：本地 VM `192.168.251.134`（etcd `:2379`、MySQL `:3306` 库 `global`+`GameDB_000101`）；本机 E2E 四进程连它。

## 六、提交前自检清单

- [ ] 相关模块 `go build ./...` 绿；改了底层则上层模块也 build 绿。
- [ ] `ci-check.ps1` 全模块 build+vet 绿。
- [ ] 新增/改动逻辑有测试守护；跨服/网络/持久化类跑真 E2E 或真依赖集成测试；并发类跑 `-race`。
- [ ] 契约有变则同步 `协议契约.md` + 契约测试。
- [ ] 加游戏功能的，对照 [游戏开发指南.md](游戏开发指南.md) 的七条架构铁律与提交前自检。

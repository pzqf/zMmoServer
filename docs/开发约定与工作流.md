## 二、核心工作方法：一个可复制的工作环

每选一块任务，按这个环推进——**它被反复验证能挖出并消灭潜伏缺陷**：

```
勘察现有实现  →  找潜伏 bug  →  修  →  加真测试守护  →  真 E2E 证明  →  更新台账/记忆
   (读代码)     (未测代码必藏)              (锁定回归)      (跨进程/真DB)     (留证据)
```

要点：

- **一次只做一块，做完做透**：编译绿 + 测试绿 + E2E 绿 + 文档更新，才算完，再开下一块。
- **未跑到的路径必藏 bug**：本项目的经验反复印证——AOI 回程、Actor 监督、断线重连、连接去重、指标接入，凡是"实现了但从没真跑过"的代码，一挖一个准。勘察时优先怀疑这类路径。
- **改动要窄、可回退**：宽面重构（如跨 8 处签名删死代码）先完整定位再动手，或拆成独立专注任务，别在长会话尾部硬上。
- **新特性默认 env/config 门控**：持久化、指标接入这类改动用环境变量（如 `ZMMO_PERSIST_CONSISTENCY=1`）门控，默认不改变原行为，便于灰度与回退。
- **业务层只做最少量**：只做够测试架构所需的业务，重点永远是整体架构，不堆玩法。

## 三、验证纪律：什么才算"证明"

**自评不可信**。项目历史上出现过"E2E 全绿 4.91/5"却是本地伪造响应、玩家从未真进入 MapServer 的情况。因此：

- **每个"完成"必须挂一个通过的测试或一次真 E2E**，不能只凭"看起来对"。
- **真 E2E = 跨进程断言**：查 MapServer 真实日志/状态、客户端真实收到的 protoId、真实 DB 行数——不是客户端本地编造的响应。
- **多模块必须逐一验证**：本仓库是多 module（各自 `go.mod` + `replace`，无 `go.work`），用一次 `ci-check` 跑全模块 build+vet。

常用命令：

```powershell
# 全模块 build+vet 门禁（8 模块全绿才算过）
powershell -ExecutionPolicy Bypass -File D:\GitHub\zMmoServer\scripts\ci-check.ps1

# 单模块 build / vet / test（免 cd，绕开 cwd 保护）
go -C D:\GitHub\zMmoServer\<Module> build ./...
go -C D:\GitHub\zEngine vet ./zNet/ ./zActor/
go -C D:\GitHub\zEngine test ./zNet/ -run <TestName> -count=1 -timeout 40s -v

# 需 DB 的集成测试用环境变量门控，未设则 t.Skip（CI 无需 DB）
$env:ZMMO_TEST_MYSQL_DSN = "root:123456@tcp(192.168.251.134:3306)/global?parseTime=true&loc=Local&timeout=8s"
```

测试写法参考：`zCommon/crossserver/codec_test.go`、`zEngine/zNet/metrics_test.go`、
`zEngine/zActor/actor_test.go`、`zCommon/consistency/sql_store_test.go`（自包含 + 强断言 + 对真实依赖验证）。

## 五、环境与工具坑（踩过的）

- **Shell**：主用 PowerShell；Bash 工具的 `cd` 常失效——定目录跑 go 用 `go -C <dir>` 或 PowerShell `Set-Location`。
- **判成败用 `$LASTEXITCODE`**，别用 `2>&1`：PowerShell 会把 go 的 stderr 包装成 error record，即便退出码 0 也显红。
- **`Remove-Item` 用绝对路径**：相对路径 + 受保护根目录（如 `e:\work`）会被拦；删仓库内临时文件可用 Bash `rm -f <绝对路径>`。
- **gopls "undefined/could not import" 是假阳性**：本仓库无 `go.work`，编辑器诊断会误报跨文件/跨模块符号找不到——**以 `go build` 为准**，忽略这类红。
- **Windows 无 C 编译器 → `go test -race` 跑不了**：`test.ps1` 检测到 gcc/clang 才加 `-race`，否则降级；`-race` 硬门禁须在 CI/Linux 跑。
- **多 module**：改了被依赖模块（zEngine/zCommon）后，务必 build 依赖它的上层模块（GameServer/MapServer 等）验证。
- **测试环境**：t1 VM `192.168.251.134`（etcd `:2379` 明文、MySQL Docker `zmmo-mysql` root/123456 `:3306`，库 `global`+`GameDB_000101`）；本机 E2E 四进程连它。

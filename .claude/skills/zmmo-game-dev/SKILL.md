# 在 realm 框架上开发游戏功能

本技能是**薄指针**。所有架构铁律、加功能配方、验收方法的**唯一真相源**是仓库文档，不在本文件复制（避免漂移）。换任何 AI/编辑器都读同一份文档即可。

> 与 `zmmo-dev` 的区别：`zmmo-dev` = 改造/硬化框架本身（成熟化改造工作环）；本技能 = **用框架开发游戏功能**（架构约束 + 加功能配方）。

## 第一步：加载真相源（按序）

1. `D:\GitHub\zMmoServer\docs\游戏开发指南.md` — **开发游戏功能的唯一真相源**（七条架构铁律 + 加功能配方，先读这份）。
2. `D:\GitHub\zMmoServer\docs\realm架构-详细设计.md` — 架构原理（分线②/实例③/回流④/无缝①/建服⑤ + 实现状态总览）。
3. `D:\GitHub\zMmoServer\docs\协议契约.md` — 跨服契约（改协议前必读；唯一编解码源 `zCommon/crossserver/codec.go`）。
4. `D:\GitHub\zMmoServer\docs\规范.md` — 目录结构 / 编码风格 / 配置表位置。
5. `D:\GitHub\zMmoServer\docs\开发约定与工作流.md` — 通用验证纪律与环境坑（自评不可信、真 E2E）。
6. 相关项目记忆（`zmmoserver-realm-track` 等：realm 进度、GameClient E2E 配方、t1 race runner）。

（跨工具通用入口另见仓库根 `AGENTS.md`。）

## 第二步：先对铁律，再按配方落地

动手前**逐条对照《游戏开发指南》第二章七条架构铁律**（权威边界 / MAP-2 单写者 / AOI 单一权威 / 分线透明 / realm 隔离 / 契约先行 / 幂等崩溃安全）——它们对应过真实缺陷，违反=重蹈覆辙。

然后按第三章配方选型（A 消息 / B 持久数据 / C 玩法 / D 地图 / E 跨服），按步骤落地。业务层只做最少量、以架构为重。

## 第三步：验收与收尾

- 按 `开发约定与工作流.md` 验证：编译绿 + 测试绿 + **跨进程真 E2E**（不凭"看起来对"）。
- realm 特有 E2E（见指南第四章）：分线隔离 / 回流落库 / AOI 单一权威 / 无缝带态。
- 并发/分线/无缝改动 → 在 **t1 race runner** 跑 `-race`（本机无 gcc）。
- `scripts/ci-check.ps1` 全模块绿；清理临时探针；同步记忆与文档。
